# P0-USER-002 verification

Canonical Site memberships now govern CMS authorization and workflow-button visibility. The legacy model, table, management endpoints and runtime fallback are retired. Test fixtures and repeatable live-review scripts now assign canonical memberships rather than writing duplicate legacy grants.

## Reconciliation and schema evidence

[Inventory](inventory.json) found 73 legacy grants, all on inactive QA identities. [Reconciliation](reconciliation.json) records their retirement without new memberships; [schema verification](schema-removal.json) confirms the table is absent, 73 provenance records remain and no unresolved grants remain. The operation used an existing active database Platform Administrator as its audited reviewer. It did not alter active institutional memberships.

`cms.0021_legacy_role_reconciliation` provides the non-authorizing provenance ledger. `cms.0022_retire_legacy_content_roles` refuses to drop a table containing unresolved or changed source grants. Migration regressions cover legacy-only users, multiple roles, existing equivalent memberships, inactive users, stale approvals, unmapped roles, idempotence, revocation while a source legacy row still exists, guarded deletion and rollback/reapplication. Rollback preserves original IDs/timestamps and does not resurrect revoked authority.

## Runtime evidence

[Browser results](browser-results.json) were recorded with real Edge, Keycloak, Next.js, Django and PostgreSQL. A generated Editor account opened Posts without a legacy grant. Its assignment was changed through the protected assignment API to Reviewer and then Publisher; the browser verified corresponding workflow controls and excluded controls for the previous role. A foreign Site was denied. Revoking the final grant removed access within the same signed-in session. Screenshots show [Reviewer controls](reviewer-controls.png), [Publisher controls](publisher-controls.png) and [revoked access](revoked-access.png).

The browser used dedicated synthetic Sites and one generated Keycloak identity. [Fixture metadata](browser-fixture.json) contains no credentials. Credentials/service tokens were kept in a mode-0600 container file and passed on stdin; [cleanup](cleanup.json) confirms the identity was disabled, memberships revoked and private file removed. Two non-login local fixture users used to seed reviewed content were disabled and their grants removed during setup.

The regression suite covers Pages, Posts, Builder draft/publication/media references, templates, revision/history access, workflow transitions, self-review restrictions, realm-claim isolation, module gates, media, Site Users and OpenAPI. [Backend results](backend-tests.xml), [migration results](migration-tests.xml), [validation summary](validation.json) and [source hashes](source-manifest.json) identify the checked code and results. A clean test database exercises the full migration graph. OpenAPI validation runs with warnings treated as errors; the baseline has no legacy role-management paths.

The expanded mixed transaction suite exposed fixture assumptions about migration-seeded modules surviving database flushes. CMS module fixtures now recreate their required module rows when absent. A content-module test was also updated to permit the independently shipped Visual Builder module. These changes preserve production module gates. Migration tests run without serialized-data restoration to avoid duplicate content-type rows during mixed migration rehearsals. Pre-Media compatibility fixtures now use historical models matching their baseline schema, and the non-publisher regression uses an explicit Editor rather than a Site Administrator. A valid-token regression also verifies that authentication cannot reactivate a disabled local member.

No frontend source contract or UI change requires a rebuild for this story; the real browser verifies the backend-driven controls. Backend schema/code deployment is required.
