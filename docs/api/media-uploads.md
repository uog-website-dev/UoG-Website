# Site media uploads

`POST /api/v1/sites/{site_id}/assets/upload/?filename={original_filename}` accepts a bounded raw byte stream. It requires the existing Site-scoped `content.media.upload` permission and enabled `MEDIA` module before reading the body. The caller must send `Content-Length` and a UUID `Idempotency-Key`; retrying with the same key and filename returns the original asset identity. Object keys are generated server-side and are never returned.

Allowed document extensions are `.pdf`, `.docx`, `.xlsx`, and `.zip`. The service checks the detected signature against the extension, validates passive PDF structure, and checks ZIP/Office package integrity, traversal paths, encryption flags, entry counts, expansion bounds, and disallowed active members. PNG/JPEG/WebP and UTF-8 plain text retain their existing support. Browser MIME types are advisory only. The configured document maximum is `MEDIA_DOCUMENT_MAX_BYTES` (default 50 MiB); the global stream bound is `MEDIA_UPLOAD_MAX_BYTES` (default 50 MiB). Both are enforced on the server while streaming.

Uploads are stored privately with a Site-scoped random attempt key and start as `PENDING`. The Media Processing worker validates stored bytes and metadata before changing the asset to `READY`. Only `READY` document assets can be selected or downloaded. `GET /api/v1/sites/{site_id}/assets/{asset_id}/download/` requires Site media-view permission, a verified checksum, and completed processing; it returns an attachment with private no-store headers. Pending, rejected, archived, cross-Site, or unverified objects are unavailable.

`GET /api/v1/sites/{site_id}/assets/upload-policy/` returns the active server limits and accepted MIME types/extensions for picker hints. Client checks improve feedback but do not replace backend checks. Failed upload attempts remain private and are reconciled by the existing upload-attempt cleanup task. Referenced assets cannot be removed; replacement should attach the new asset to a new content revision, which retains the previous revision reference under the CMS retention policy.
